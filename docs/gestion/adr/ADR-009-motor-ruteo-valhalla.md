# ADR-009: Motor de ruteo auto-hospedado (Valhalla) invocado solo por el backend

- **Estado:** Aceptada según el C4 (N2/N3: motor de ruteo Valhalla/pgRouting) y el docker-compose del repo; el perfil de ruteo accesible está Pendiente de configurar.
- **Contexto:** El requisito núcleo es calcular rutas **peatonales** que excluyan barreras críticas según el perfil del usuario (RNF-21/26), a ≤ 3 s con 200 usuarios concurrentes (RNF-01); los motores genéricos (Google Maps, Waze) no evita barreras de accesibilidad.
- **Decisión:** **Valhalla** auto-hospedado en Docker (contenedor `omnitravel-valhalla`, puerto 8002, con `valhalla_service /data/valhalla.json`), construido con extractos OSM de la región objetivo (Quindío, inicio por Armenia). El cliente móvil **nunca** llama a Valhalla: siempre `POST /api/v1/routes` al backend NestJS, que traduce el perfil del usuario a parámetros de restricción anónimos, gestiona el `costing` peatonal (hoy `auto`, a migrar) y mapea errores/simulaciones (`warnings[]`, `BARRIER_BLOCKED`, RNF-17/27).
- **Alternativas:** API de ruteo comercial (Google/Mapbox Directions); OSRM con perfil peatonal; pgRouting sobre el propio PostGIS.
- **Justificación:** Valhalla soporta costing peatonal personalizable y ejecuta localmente (sin consumo por llamada ni envío de datos del viajero a terceros, compatible con RNF-07/10); ya está provisionado en la infraestructura del equipo.
- **Consecuencias:** Hay que operar los tiles (extraer/construir el grafo de OSM) y definir el perfil de ruteo con la lógica de barreras (cómo marcar los segmentos con barreras críticas y cómo excluirlos de la ruta); el backend actúa como proxy única para control de rendimiento y consistencia con el contrato (`RouteResponse` compatible con Valhalla + `warnings`).
